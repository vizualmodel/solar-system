# Satellite models and historical visibility

The app bundles NASA's [International Space Station (B)](https://science.nasa.gov/3d-resources/international-space-station-iss-b/) (NASA/Michael D. Carbajal) and [Hubble Space Telescope (A)](https://science.nasa.gov/3d-resources/hubble-space-telescope-a/) (DigitalSpace Corporation, distributed by NASA). Source GLBs are stored in `public/models/`; run `node scripts/fetch-satellite-models.mjs` to download replacements. Review NASA's [media usage guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/) for redistribution; no endorsement is implied. These are visual models, not flight engineering models.

Three.js loads these local files only when the spacecraft projects to at least 80 pixels in diameter. The original procedural silhouettes remain in use at a distance and while loading or after a load failure. Draco decoding uses the locally bundled Three.js decoder (Apache 2.0), without a CDN. Detailed geometry is centred and uniformly normalised to approximately 109 m for the ISS and 13.2 m for Hubble. Attitude, assembly and servicing history are illustrative. Components sharing a material are batched to reduce draw calls (18 ISS / 5 Hubble). Hubble includes embedded texture images.

The ISS source contains seven loose authoring cylinders (`bendedtru1/2/3`, `bendedtrus`, `pCylinder1/2/8`) at y≈41, detached from the station at y≈−4..26. `iss-materials.ts` removes exactly these objects before computing bounds; every station triangle is retained. The cleaned model is aligned with the procedural LOD and spans approximately 109 × 14.6 × 71.7 metres. Its identical gray Blinn placeholders are replaced with opaque, untextured PBR materials: aluminum structure, matte off-white insulation and radiator coatings, muted gold foil, dark equipment/glass, and amber-brown solar blankets. Slot assignments are visual approximations, not an engineering materials inventory.

Simulation state and controls stay in AU, while `render-units.ts` scales the GPU scene and a separate rendering camera to metres. Three.js logarithmic depth computes `log2(1 + clip.w)`; at ISS viewing distances expressed in AU, float32 rounds that sum to 1, collapsing surface depth. Metre rendering resolves millimetre separations at close-up distances while retaining the solar-system far plane. Eclipse shader surface coordinates are converted back to AU, preserving their existing geometric calculations. Numeric regression tests include 24-bit depth quantization and unchanged screen projections.

`node --import tsx scripts/preview-iss.ts` produces an offline software preview for geometry and color inspection. It does not substitute for a browser/WebGL check of PBR lighting or shader compilation.

No Blender installation is required. For future artist edits: import a source GLB into Blender, preserve UVs/materials, remove hidden internal geometry if needed, apply transforms, keep metres as scene units, and export glTF 2.0 Binary with embedded textures. Replace the corresponding file, run the model decoding tests, and visually review the close-up. Keep the dimensions and centring checks. The runtime accepts uncompressed GLB as well as Draco-compressed GLB.

Visibility begins on 25 April 1990 for [Hubble's deployment](https://science.nasa.gov/missions/hubble/april-25-1990-deployment-of-the-hubble-space-telescope/) and 20 November 1998 for the first ISS module, Zarya. Dates have one-day precision. The timeline and bundled Horizons planetary/moon samples cover 1990–2031. `node scripts/extend-historical-data.mjs` prepends historical samples while preserving accepted 2025–2031 samples. `npm run data` should use that same full range when regenerating the dataset.

Within ±3 days of each bundled satellite snapshot, positions use SGP4. Outside it, an elliptic two-body orbit anchored to the nearest boundary state preserves position and velocity continuity. This prevents decades of atmospheric-drag extrapolation from producing decay or invalid states. It does not reconstruct historical phase, altitude, reboosts or precession, and is explicitly labelled illustrative in the UI. No retirement date is predicted; availability extends to the supported timeline end.

Use the **ISS close-up — travel alongside the station** scenario. Setup preserves the shared date and other views, selects true size, places the camera about 300 m away, follows the ISS origin each frame, and sets exactly one simulated second per real second. Setup pauses; press Play to move. Camera zoom limits and near clipping allow metre-scale inspection.

Live validation and activation must use the companion's `build_candidate` / `activate_candidate` workflow when its owning browser is connected. Do not start another server to replace it.
